# @bolyra/evc-conformance

Prove an External Verifier Contract v1 **host** conforms — one command, any
language, no install.

```sh
npx @bolyra/evc-conformance --host "/path/to/your-host --flags"
```

Runs the 28 `host_behavior` vectors against your host: verifier spawning,
timeout and output-bound enforcement, fail-closed handling of every
misbehaving-verifier class, closed decision schema, and reserve-before-act
nonce semantics. Exit `0` when everything passes, `1` on any failure — drops
straight into CI.

```sh
npx @bolyra/evc-conformance                  # self-test the bundled reference host
npx @bolyra/evc-conformance --host "..." --json   # machine-readable result on stdout
```

The `--json` output includes the vector-set version, count, and SHA-256, so a
CI run states exactly which vector set it passed.

## What your host must do

Honor the Host-Under-Test convention: read the `HUT_*` environment variables,
spawn the verifier named in `HUT_VERIFIER_CMD`, enforce the timeout and
output bound, reserve nonces before acting, and emit exactly one decision
object on stdout. The full pass path — contract summary, failure classes,
troubleshooting, CI snippet — is
[`spec/IMPLEMENTER.md`](https://github.com/bolyra/bolyra/blob/main/spec/IMPLEMENTER.md);
the normative contract is
[`spec/external-verifier-contract-v1.md`](https://github.com/bolyra/bolyra/blob/main/spec/external-verifier-contract-v1.md).

## Provenance

These are the Bolyra-maintained EVC v1 host conformance vectors. Everything
under `vendor/` is a checksummed snapshot of the monorepo's `spec/` directory
(see `MANIFEST.json`); it is regenerated by `npm run sync` and verified by
`npm run sync:check` in CI — never edited by hand. The full 112-vector suite
(handshake, signature, Merkle, delegation) lives in the monorepo and tests
the reference implementation, not your host.

If your host goes green, open an issue on
[bolyra/bolyra](https://github.com/bolyra/bolyra) — we would like to know,
and we will list it.
