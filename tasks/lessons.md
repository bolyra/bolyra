## 2026-07-18 — squash scout/agent branches before opening an external PR
- Incident: openai/openai-agents-js#1495 opened with 5 commits — 4 were internal "rescout:" scout-progress commits ("guardrails CLEAN", "awaiting subagents") + a committed rescout-notes.md. Public on an OpenAI repo ~20 min until the founder caught it.
- Root cause: stripping the notes file from the FINAL commit's tree does not remove the earlier scout commits from branch HISTORY. `git reset --soft main` reset to a STALE local main that already had them, so it didn't flatten.
- Rule: before pushing any agent-built branch as a PR — `git reset --soft <upstream>/main` (real upstream, not local main), stage ONLY deliverable files, `git rm --cached rescout-notes.md`, strip Co-Authored-By, then VERIFY `git log --oneline <upstream>/main..HEAD` (== deliverable only) + `git diff --stat` (grep for rescout|scout|notes = 0) BEFORE force-push, and re-check `gh pr view --json commits,files` AFTER.
- **`npm install --package-lock-only` anchors to an existing `node_modules` tree.** 2026-07-23: fresh-deleted lockfiles kept resolving vulnerable `brace-expansion 2.1.1` because Arborist treats installed packages as resolution hints; the same regen with `node_modules` removed resolved patched `2.1.2`. CI audits pass while local lockfiles stay stale for exactly this reason. True-clean regen = `rm -rf node_modules package-lock.json && npm install --package-lock-only`.
- **Freshly published patch versions lag npm's install path.** `npm view` (full packument) showed `brace-expansion@2.1.2` ~90 min before transitive resolution would pick it up (abbreviated-packument CDN propagation). Don't debug "why won't npm pick the patch" in the first hours after an advisory's fix ships — probe with a scratch `npm install pkg@range` first.
- **`--package-lock-only` lockfiles are NOT `npm ci`-complete.** 2026-07-23, PR #86: lock-only regen omits optional native/wasm subtrees (`@emnapi/*` via `@napi-rs/wasm-runtime`), so `npm ci` fails EUSAGE "lock file missing" in CI while local `npm install`-based tests pass. A committed lockfile must come from a FULL install (`rm -rf node_modules package-lock.json && npm install`); verify with `rm -rf node_modules && npm ci` before pushing lockfile changes.
- **Stale exact-pin overrides become the vulnerability.** 2026-07-23: the May cleanup's `fast-uri: 3.1.2` / `hono: 4.12.29` exact overrides later pinned newly-advisoried versions. Rule (Codex-ratified): checking and bumping/dropping stale override pins is part of EVERY Dependabot triage. Also: forcing a major via override (e.g. `@hono/node-server` 1.x→2.0.5) is legitimate when the parent range blocks the only patched version, but must be gated on the package's own test suite.
